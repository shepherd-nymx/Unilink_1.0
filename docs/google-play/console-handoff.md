# Next steps in the new organisation Play Console account

The owner has registered an organisation account and confirmed this is UniLink's first-ever Play upload. No prior release key is available. These steps are a handoff, not a statement that Google has verified or approved the account/app.

1. **Check account verification.** Open <https://play.google.com/console> and the home-page account setup tasks. Complete any organisation, identity, contact, website or payment checks Google still requests. If the status is unclear, note the exact task names shown. Registration alone does not establish completed verification.
2. **Create the application entry.** Use the intended publisher account, app name `UniLink`, appropriate English listing language, app type and pricing. The grocery service can charge for physical orders/delivery separately from the app's download price. The Android application ID supplied by the bundle will be `com.unilinkbase.twa`; confirm it before the first upload.
3. **Prepare the upload key on the owner's machine.** See `../../android-twa/README.md` and its local `scripts/create-upload-key.sh`. Keep the key and password privately and backed up outside Git. Use this key to sign the unsigned AAB. The unsigned AAB and a debug APK are not accepted as the production upload.
4. **Configure Play App Signing.** For this first release, use Google-managed app signing unless there is a specific signing requirement. The upload key signs the file you submit; Google's separate app-signing key signs the application users install.
5. **Upload to internal testing first.** Complete the tasks Play Console requires, using a signed AAB. Do not choose a production release yet. This organisation account is not subject to the 12-testers/14-days rule specifically imposed on newly created personal accounts, but test the actual installed application and follow the requirements shown in this account.
6. **Confirm the website/app association.** From Play Console's App integrity/App signing information, copy the public app-signing certificate's SHA-256 fingerprint. It is safe to share that fingerprint (not the private key). It must appear under `com.unilinkbase.twa` at `https://www.unilinkbase.com/.well-known/assetlinks.json` for full-screen trusted launch. Preserve existing valid entries. Verify with an application installed from the Play test track.
7. **Finish the release blockers.** The current live website still needs the documented password-authentication fix, account-and-data-deletion coverage, functioning public policy/deep links, correct icon sizes and real-device checks. Review the listing, App access credentials, Data Safety, target audience, ads declaration and content rating before requesting production review.

Sources: [account verification](https://support.google.com/googleplay/android-developer/answer/13628312), [app setup and app bundles](https://support.google.com/googleplay/android-developer/answer/9859152), [Play App Signing](https://support.google.com/googleplay/android-developer/answer/9842756), [personal-account testing requirement](https://support.google.com/googleplay/android-developer/answer/14151465), [TWA verification](https://developer.chrome.com/docs/android/trusted-web-activity/quick-start).
